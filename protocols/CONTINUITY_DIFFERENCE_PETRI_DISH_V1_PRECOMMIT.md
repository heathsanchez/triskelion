# CONTINUITY + DIFFERENCE PETRI DISH V1 — prospective precommit

Status: **FROZEN BEFORE IMPLEMENTATION OR OUTCOME EXECUTION**

## Question

Can a developmental system supplied with only:

[
oxed{	extbf{Continuity} + 	extbf{Difference}}
]

plus an external verifier and one generic recombination law regenerate the developmental behaviors that earlier Triskelion experiments represented explicitly as differentiation, mediation, integration, lineage, recombination, and recursive compounding?

The experiment is designed to falsify the favored pair. A smaller or ablated seed that matches the full seed counts against the hypothesis.

## Candidate primitives

### C — Continuity

The current inherited executable state.

It contains:

- immutable primitive observations supplied by the world interface;
- previously verified generated children;
- the direct verified parent relationships of those children.

A generated child joins C only after external verification.

### Δ — Difference

A verifier-delivered counterexample to the current candidate:

[
Delta=(	ext{encounter row},	ext{expected consequence}).
]

The developmental system is never handed the hidden target relation or a target-specific expression.

If authority rejects a proposal but withholds the counterexample content, no Δ has been supplied.

## External authority

The exact verifier is outside the candidate nucleus.

Proposal is not authority.

The verifier may return only:

- VERIFIED, or
- one exact counterexample row and expected consequence.

An OPEN/incomplete authority packet cannot promote a child.

## One fixed generative law

The only developmental law supplied internally is a generic finite recombination procedure:

[
G(C,Delta^*) ightarrow 	ext{candidate child},
]

where (Delta^*) is the accumulated residual set for the current encounter.

G has no world-specific operators and no named D/M/I stages.

It:

1. enumerates unordered pairs of currently inherited executable features in stable order;
2. retains only pairs consistent with all accumulated residuals;
3. for each surviving pair, constructs the least extensional finite relation consistent with those residuals, canonically completing unseen input combinations;
4. proposes the least stable candidate;
5. receives VERIFIED or a new Δ from external authority;
6. on VERIFIED, returns the child.

The child is admitted into C only when Continuity is enabled.

The verified child may then participate in later recombination.

This **child re-entry** is part of the operational meaning of Continuity, not a third candidate primitive.

## Post-hoc phenotype test

The implementation must not call the imported D/M/I nucleus to solve the primary CD episodes.

After the run, traces are classified for three behaviors:

- **D-like phenotype:** residuals causally eliminate insufficient parent distinctions and the verified child has a minimum sufficient parent pair.
- **M-like phenotype:** the system constructs a novel extensional relation over that pair.
- **I-like phenotype:** after verification the child becomes executable inherited state and later appears as a parent.

If all three emerge, this is evidence that D/M/I can be a phenotype of the smaller C+Δ seed in this finite setting.

## Petri-dish worlds

Use the same five source-distinct finite adapters already frozen in CROSS-WORLD NUCLEUS INVARIANCE V1:

1. binary Cartesian;
2. ternary Cartesian;
3. symbolic string;
4. temporal history;

The CD solver source is identical in every world.

World adapters provide only primitive feature vectors and carrier rows. They do not provide world-specific developmental operators.

## Guaranteed pair-generated hidden children

Each hidden child is generated as an opaque extensional function of exactly two declared parents.

Output tokens use a fresh five-symbol opaque alphabet generated mechanically from a frozen hash.

A hidden child is admissible only when:

1. it is novel relative to every active feature;
2. both declared parents are essential;
3. the declared pair is the unique sufficient active feature pair for that child.

The world generator may advance only to the next deterministic hash counter when these structural conditions fail.

This design is frozen before execution specifically to avoid selecting worlds based on nucleus performance.

## Twin lineages

Each world begins with two exact copies of the same initial inherited state:

[
C^A_0=C^B_0.
]

They receive different encounter histories.

### History A

[
(q0,q1)	o A1
]
[
(A1,q2)	o A2
]
[
(A2,q3)	o A3
]

### History B

[
(q0,q4)	o B1
]
[
(B1,q5)	o B2
]
[
(B2,q2)	o B3.
]

For worlds exposing fewer than q0…q5, the adapter deterministically derives additional opaque primitive observations by fixed value permutations before any outcome is inspected. These derived primitives are part of the world interface, not learned developmental state.

Required twin property:

- both twins remain externally correct;
- their generated inherited states differ after their different histories.

This tests variation from history under the same seed law.

## Recombination challenge

After A3 and B3 are sealed, create a combined inherited state containing both verified lineages.

Generate:

[
(A3,B3)	o K.
]

The target K must have (A3,B3) as its unique sufficient active pair.

Matched controls:

- A-only state;
- B-only state;
- FLAT-UNION state with the same capability contents but no verified lineage metadata;
- full combined state.

Because the CD law searches executable feature pairs rather than ancestry labels, lineage metadata must not be necessary merely to solve K. The causal claim is about **inherited executable variation meeting inherited executable variation**.

K must be novel relative to both parental lineages.

## Child-becomes-parent challenge

Then generate:

[
(K,q0)	o Z.
]

K must be the unique sufficient generated parent for Z.

Causal ablation:

1. remove K only;
2. re-run Z under identical resource and authority conditions;
3. Z must fail;
4. restore exact verified K;
5. Z must verify again.

This is the recursion criterion.

## Candidate seed arms

Every sealed world executes:

### NONE
No retained generated state and no counterexample content.

### C_ONLY
Generated children may be retained only if verified, but rejections return no counterexample content. The proposal process therefore cannot refine itself from error.

### D_ONLY
Correct counterexamples are available, but generated children are discarded after each encounter. Every episode starts from world primitives only.

### CD
Full candidate pair: retained verified state + correct counterexamples.

### CD_NO_REENTRY
Correct counterexamples and transcripts exist, but verified generated children are not admitted as future executable parents.

### C_SHAM_D
Continuity is present, but each verifier counterexample is deterministically paired with the expected consequence from a different counterexample row whenever such a mismatch is available. A candidate is still admitted only by the exact external verifier.

### CD_COLD_TWIN
Full CD mechanism but developmental state is reset to initial primitives before each encounter.

### ORACLE
Receives the declared true parent pair and exact relation. Upper bound only.

All arms share the same carrier, hidden targets, external authority, episode order, and proposal/check accounting.

## Resource limits

Per encounter:

- maximum 128 verifier counterexamples;
- maximum complete active parent-pair frontier;
- one verified generated child may be admitted;
- no recursive reconstruction of missing ancestors within the same encounter.

Failure to verify within the frozen budget is a scientific failure for that arm.

## Variation measurements

Variation is measured at three levels.

### V1 — history variation

Starting from identical initial state and identical law:

[
H_A
eq H_B
Rightarrow
C^A_3
eq C^B_3.
]

### V2 — recombination variation

K must be:

- absent from lineage A;
- absent from lineage B;
- novel in the combined state before recombination;
- externally verified after recombination.

### V3 — descendant variation

Z must depend causally on K and therefore on both ancestral histories.

## Emergent lineage

The CD solver records only the parent pair it actually used when a child verifies.

The resulting ancestry graph is compared after sealing against the hidden evaluator DAG:

[
q0,q1	o A1	o A2	o A3
]
[
q0,q4	o B1	o B2	o B3
]
[
A3,B3	o K
]
[
K,q0	o Z.
]

Exact equality is a post-hoc gate.

No hidden ancestry edge may be inserted into the solver state after the fact.

## Same-law common challenge

After the twin histories but before recombination, both twins receive an identical sealed common target generated from the same primitive pair.

Both must eventually verify the same protected consequence.

Their internal developmental ancestry is allowed to differ.

This separates:

[
	ext{same law / same warrant}
]

from:

[
	ext{same history / same form}.
