Founder identity is not manually named or selected by semantic interpretation.

A founder is any blindly recovered verified schema satisfying the frozen utility threshold.

## Workload

Run 20,000 exact episodes.

### Phase F — founder acquisition, 1–2,000

Expanded D+GROUND structures only.

Blindly recover and verify useful founder schemas.

### Phase G — genealogy growth, 2,001–12,000

Every target episode is generated from two installed parents through the frozen reproductive constructor.

Recently born capabilities receive 60% of parent-selection mass; the remaining 40% is distributed across the full installed archive.

This is intended to make child→parent recursion observable without choosing semantic identities.

### Phase S — ecological shift, 12,001–16,000

Change only the deterministic parent-age weighting and argument projection distribution.

No capability identities are privileged.

New children may enter and old capabilities may be repriced.

### Phase R — revocation, event 16,001

Choose the deepest currently installed non-founder capability by:

1. greatest ancestry depth;
2. greatest descendant count;
3. lowest capability ID as deterministic tie-break.

Inject exact counterevidence invalidating that capability's warrant.

Before the next execution:

- revoke it;
- recursively revoke every dependent descendant;
- preserve every capability outside its descendant cone.

Then continue for 2,000 recovery episodes.

### Phase H — held-out, 18,001–20,000

Freeze the archive.

Generate new exact episodes from the same reproductive law using unseen salts.

No promotion is allowed.

## Matched controls

### NO_REENTRY

Verified children are recorded but never become eligible parents.

Founder capabilities remain usable.

### DEPTH1_ONLY

Children may be used for execution but never as parents.

### NO_ANCESTRY

Execution may reuse verified semantics, but parent edges are discarded. At revocation only the selected capability itself can be removed; descendants cannot be identified from ancestry.

### COLD

No persistent derived capabilities.

### RANDOM_REVOKE

At event 16,001 revoke a depth-matched capability chosen by frozen hash rather than the greatest-descendant target.

### NO_WARRANT

Install zero derived capabilities.

## Costs

For an episode:

- transparent D execution cost = number of D nodes in fully expanded expression;
- invoking an installed verified capability = 1 abstract developmental instruction;
- VERIFY = 1;
- PROMOTE = 1;
- revocation bookkeeping is reported separately.

This remains an abstract developmental cost model. It is not a CPU-cycle claim.

## Causal ancestor knockout

At depths 4, 8, 16, and 32, if reached:

1. select the oldest ancestor on the deepest lineage;
2. evaluate 100 frozen descendant episodes with the full archive;
3. remove that ancestor **and its descendant cone**;
4. rerun the same episodes;
5. restore the cone;
6. rerun again.

Required causal signature:

[
C_{	ext{removed}}>C_{	ext{full}}
]

and restoration returns the original cost and exact consequences.

No wrong answer is permitted in any arm; loss of capability must fall back to transparent expansion.

## Genealogical recombination

Whenever two installed capabilities have disjoint non-founder ancestry cones, the environment periodically attempts a child using one from each lineage.

Record:

- cross-lineage children;
- whether they later become parents;
- whether they increase maximum depth;
- whether removal of either lineage blocks the recombinant fast path.
