# RBS_SELF_TEST_001_V3 — Prospective Controller Causality

## Status

**PRECOMMITTED BEFORE OUTCOME INSPECTION**

Purpose: test the Rigorous Breakthrough Stack / Developmental Controller as a solver policy using the same epistemic standards it applies to object-level capabilities.

This protocol does not treat prior RBS/Triskelion successes as held-out validation. They are development evidence only.

## Primary causal claim

Under matched information and resource budgets, the controller transition

`failure -> structured residual -> rival diagnosis -> smallest separating experiment -> external verifier -> ratchet`

causally increases verified future capability gained per unit cost relative to simpler controls.

A positive result requires prospective verified effect, not retrospective explanatory fit.

## External task stream

Primary corpus: the already-frozen 501-bug BugsInPy universe used by the natural developmental programme.

Selection rule:

1. preserve the previously frozen corpus identity and deterministic ordering;
2. begin strictly after all episodes whose protected semantic/source content has already influenced controller design or hypothesis selection;
3. scan forward mechanically in that frozen order;
4. eligibility may use only pre-existing infrastructure/qualification rules: designated historical runtime launches, fixed commit passes, buggy commit fails, native verifier executes, and required artifacts exist;
5. infrastructure failures are recorded as `INFRASTRUCTURE_NULL` and scanning advances without semantic cherry-picking;
6. no protected source body, fix, semantic label, or outcome may be inspected to decide inclusion;
7. once an episode becomes apparatus-valid it enters the experiment regardless of whether any arm later succeeds.

The first apparatus-valid episodes satisfying these rules form the prospective stream. No manual replacement for difficulty or mechanism fit is allowed.

## Controller arms

All arms receive the same base model, task-visible evidence, tool interface, verifier interface, context ceiling, model-call ceiling, candidate budget, wall-time ceiling, seed schedule, and permitted corpus metadata.

### A — LOCAL
Directly solve the current task. No persistent structured residual taxonomy, causal lineage, explicit closure gate, or frontier projection.

### B — RAW_HISTORY
A plus an equal-size/token raw record of previous attempts and verifier outcomes. No structured developmental interpretation is supplied.

### C — RBS_FULL
Apply the frozen controller policy: interface/quotient where applicable; residual classification; rival explanations; closure-before-invention; smallest deciding test; external verification; ratchet; projection; lineage update.

### D — RBS_SEPARATOR_ABLATION
Same information, memory allowance, candidate set, and total budget as C, but the structured diagnosis may not select the next action by rival-separating value. Candidate actions are consumed in a precommitted deterministic shuffled order until the same budget is exhausted.

### E — SHUFFLED_STATE
Same serialized developmental-state size as C but prior episode records are deterministically shuffled across causal lineage fields so that quantity of memory is preserved while trajectory structure is destroyed. Impossible/malformed records are not introduced; only lineage association is shuffled.

## Primary endpoint

Primary endpoint: **verified developmental yield per fixed model-call budget**.

For each entered episode record:

- terminal verifier success/failure;
- model calls;
- verifier calls;
- candidate count;
- input/output tokens;
- wall time;
- solver-state transition;
- newly admitted/scoped/rejected capability or law;
- whether that state causally affects a later episode under ablation.

The primary comparison is the number of externally verified terminal successes plus separately identified verified solver mutations that cause a later verified success within the same frozen call budget. Raw residual reduction does not count as success.

Secondary cost vector:

`C = (model_calls, verifier_calls, candidate_count, tokens, wall_time)`

No secondary measure may replace the primary endpoint after execution.

## Strong pass condition

`METHOD_CAUSAL_PASS` requires all of:

1. apparatus-valid prospective episodes;
2. C outperforms A on the primary endpoint;
3. C outperforms B, so equal-sized raw history does not explain the gain;
4. C outperforms D, so the residual/rival/separator transition has identifiable causal value;
5. C outperforms or materially differs from E in the precommitted direction when trajectory structure is part of the gain;
6. total matched-budget accounting rules out extra calls, tokens, tools, source information, or verifier work as the explanation;
7. at least one acquired/scoped solver mutation from an earlier entered episode changes a later verified discovery frontier, and ablating that state removes or materially raises the cost of the later discovery;
8. replay succeeds from recorded artifacts.

## Classified non-pass outcomes

- C > A but C ~= B: `MEMORY_SUFFICIENT_RIVAL`
- C > A/B but C ~= D: `SEPARATOR_MECHANISM_NOT_CAUSAL`
- C > A/B/D but C ~= E where trajectory is claimed: `TRAJECTORY_STRUCTURE_NOT_IDENTIFIED`
- apparent gain vanishes under total-cost matching: `R12_COST_DISPLACEMENT`
- residuals become sharper but terminal verified capability does not improve: `NON_TERMINAL_META_GAIN`
- protected semantic regression: `HARMFUL_CONTROLLER_POLICY`
- required runtime/verifier/harness failure: `INFRASTRUCTURE_NULL`
- insufficient entered episodes/deciding comparisons: `INCONCLUSIVE`

Negative outcomes remain permanent evidence and may revise the controller; they may not be overwritten by a repaired protocol.

## Anti-contamination boundary

After this precommit, no change to arm definitions, eligibility, primary endpoint, ordering, or strong pass conditions may use protected semantic outcomes from the entered stream.

A scientifically motivated revision creates a new protocol/version and leaves this run intact.

## Self-application verdict rule

RBS is not promoted because it generated this protocol. It is promoted only by prospective outcomes under this protocol.

If the protocol falsifies a central RBS mechanism, the correct RBS response is to preserve the evidence, revise or demote the mechanism, and prospectively retest the revised controller.
