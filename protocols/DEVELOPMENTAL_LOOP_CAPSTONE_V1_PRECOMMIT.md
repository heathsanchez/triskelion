# DEVELOPMENTAL_LOOP_CAPSTONE_V1 — prospective precommit

Frozen before implementing or executing the capstone outcome code.

## Question

Can one exact bounded system demonstrate the whole reversible developmental loop, rather than isolated primitives: verifier experience -> non-preenumerated construction -> persistent effective-language growth -> protected downstream gain -> causal remove/restore -> counterevidence-driven scope revision, while matched controls separate persistent executable structure from cold search, raw episodic memory, and causally corrupted verifier feedback?

## Inherited substrate

This protocol extends EFFECTIVE_LANGUAGE_EXPANSION_V1 without changing its scientific boundary.

- Semantic world: all 256 three-input Boolean functions.
- Initial effective language L0: constants/variables plus NOT/XOR under exact arbitrary composition.
- Exact Cl(L0) must contain 16/256 functions.
- General construction substrate U: constants/variables plus NOT/XOR/AND, enumerated only by generic syntax and size. No target-specific named operator may appear in U.
- External verifier: exact Boolean behavior on rows; the constructor receives only counterexample rows and expected outputs, not the hidden truth table or hidden U expression.
- Acquisition target K: mechanically selected by a frozen hash rule from U semantics outside exact Cl(L0). Selection may not inspect later capstone outcomes.
- Downstream target O2: mechanically selected after K admission from semantics reachable in the bounded installed language L1 but not in exact Cl(L0), excluding K itself.

## Four matched arms

All arms inherit the same U, verifier semantics, downstream target, and fixed resource accounting.

1. COLD — starts from L0, no acquisition transcript and no installed K.
2. MEMORY — receives the complete acquisition transcript and sealed source expression as episodic text, but the expression is not installed as a primitive. It may inline/reconstruct that expression, paying ordinary U syntax cost each use.
3. CORRUPTED — receives the same number and type of acquisition observations, but proposal-to-consequence pairing is deterministically permuted across the frozen acquisition trace. It may synthesize only from that corrupted evidence and may install only a candidate independently verified by V.
4. DEVELOPMENT — receives the coherent verifier sequence; if a candidate is independently verified, it is installed as a unit-cost reusable primitive K in L1.

The distinction between MEMORY and DEVELOPMENT is operational, not informational: memory may know the source text but cannot alter the installed effective language. The downstream comparison therefore measures bounded reachable program cost, not whether memory can quote K.

## Fixed downstream budget

Let B be the minimum installed-language syntax size at which the DEVELOPMENT arm reaches mechanically selected O2. Freeze the comparison budget to B. Recompute COLD and MEMORY reachability at exactly B under their respective languages/cost accounting. No arm receives extra budget after outcome inspection.

Required separator:

- DEVELOPMENT reaches O2 within B.
- COLD does not reach O2 within B.
- MEMORY does not reach O2 within B when K must be inlined/reconstructed at ordinary U syntax cost.
- CORRUPTED does not receive credit merely for synthesizing any program: only an independently V-verified candidate may be installed, and protected O2 must still be evaluated under the same B.

If MEMORY reaches O2 within B, the memory-vs-development separator is a valid negative; do not alter B or redefine memory.

## Causal ablation

After DEVELOPMENT reaches O2:

- remove only installed K and recompute under the same B: O2 must become unreachable;
- restore exactly the sealed K and recompute under the same B: O2 must become reachable again.

No other state may change during remove/restore.

## Counter-ratchet / applicability phase

A second context bit c is introduced only after K and O2 are sealed. The operation K is useful in c=0. A protected c=1 behavior is selected mechanically from exact L0 semantics and therefore must not be replaced by K.

The developmental state initially has the maximally broad scope hypothesis ANY because only c=0 acquisition evidence has been observed. The scope grammar is frozen and generic: {ANY, c==0, c==1, NEVER}. No target-specific predicate may be added.

Then reveal one protected c=1 counterexample. The controller must evaluate the frozen scope grammar against all accumulated verifier evidence and choose the least restrictive surviving scope under the frozen order ANY < c==0 < c==1 < NEVER where validity dominates permissiveness.

Required counter-ratchet behavior:

- ANY is invalidated by protected evidence;
- c==0 survives;
- learned capability K itself remains semantically valid in its admitted scope;
- the protected c=1 L0 behavior is restored/preserved;
- deleting the scope revision recreates the protected failure.

If no surviving scope exists, REVOKE is the correct outcome and is still a scientifically valid counter-ratchet event. The capstone PASS below, however, requires the mechanically constructed world to admit the frozen c==0 scope.

## Development-changes-development phase

O2 counts as the second-generation capability only if:

- O2 is outside exact Cl(L0),
- O2 is reachable within budget B only after K is installed,
- ablation of K removes that reachability,
- restoration of K restores it.

This is the bounded claim that acquisition of O1=K changes the reachable space in which O2 can be discovered/constructed.

## Headline gates

G1 exact old-language obstruction.
G2 coherent verifier feedback synthesizes a V-verified non-preenumerated K from generic U.
G3 installing K changes the effective language and makes O2 reachable within frozen B.
G4 COLD does not reach O2 within B.
G5 MEMORY, despite complete episodic transcript/source, does not reach O2 within B under ordinary non-installed syntax cost.
G6 CORRUPTED feedback does not earn the same protected downstream result under matched admission rules.
G7 targeted K ablation removes O2 reachability and exact restore returns it.
G8 protected counterevidence invalidates ANY and induces c==0 (or, if no valid scope exists, scientifically records REVOKE; headline PASS requires c==0 in this frozen world).
G9 removing the learned scope revision recreates the protected c=1 failure.
G10 O2 satisfies the bounded development-changes-development criterion.

Verdict `PASS_DEVELOPMENTAL_LOOP_CAPSTONE_V1` iff G1-G10 all pass.

Any failed gate produces `VALID_NEGATIVE_DEVELOPMENTAL_LOOP_CAPSTONE_V1` with the failed gates disclosed. No same-target protocol edits or rescue reruns are allowed.
