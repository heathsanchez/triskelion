# Triskelion / Metalogic Research State

_Last reconciled: 2026-08-14 16:15 NZST_

## Current strongest synthesis

Triskelion is testing a **verified developmental capability system**: externally verified experience can alter an explicit algebra of capabilities, laws, scopes, distinctions and constructors, and those changes can alter what becomes reachable or discoverable later.

The governing loop is:

`seek/act -> external result -> residual -> closure test -> obstruction -> minimal construction -> verification -> install/retain -> invoke -> revise/revoke -> changed future discoverability`

Neural proceduralization is downstream:

`explicit verified capability/state -> compiler Γ(model) -> optional neural realization`

The explicit object remains authoritative; weights/checkpoints are implementations/caches, not the source of truth.

A useful current state is:

`A_t = (O_t, L_t, S_t, Π_t, K_t, D_t, V)`

where `O_t` are verified capabilities/operators, `L_t` scoped composition/equivalence laws, `S_t` applicability/conflict/revision/lifecycle conditions, `Π_t` verifier-induced operational distinctions, `K_t` constructor machinery, `D_t` discovery policy/budget and `V` external verifier authority.

The key predicates are `Closure(A_t)`, `Discoverable(A_t)` and `Constructible(K_t)`.

## What is established in bounded form

### Closure before invention

The `even_pairs / MAP_PAIRS` negative remains constitutional: if a target is already expressible by lawful composition, do not promote a new primitive. Novelty must be justified against the frozen effective language.

### Capability formation outside old closure — V51

V51 constructed `< -> <=` after proving the frozen old token-position algebra could not express it because old transformations preserved token-value multisets. The operator was committed from external obstruction, transferred to sealed Requests, survived causal tests, and later counterevidence triggered revision/revocation logic. Construction remains inside a supplied generic token-emission substrate; this is not unrestricted invention.

The V49/V50 lead-in matters: V49 committed the learned category before Requests was opened and demonstrated cold failure -> warm success -> ablation failure -> later revocation; V50 generated HELP/HARM supervision from executable verifier transitions rather than supplied class labels.

### Source-distinct causal reuse and discoverability growth

The external `EXCEPTION_FLOW` stream established a capability formed from one independently authored package and later causally required by another, with ablation restoring failure.

V33/V34 established source-distinct discoverability growth: acquired capability changed which next obstruction the frozen discovery process could expose.

### Constructor-family abstraction and verifier-induced ontology

V35–V39 moved from exact instances to reusable constructor families and operational interfaces. V39 used neutral probes plus Python compilation to induce operational equivalence classes from verifier responses rather than supplied semantic labels.

V40–V50 progressively weakened experimenter semantics: named scopes/categories gave way to generic relations, opaque labels, raw lexical source, site mining, sealed transfer and outcome labels generated by executable verifier transitions.

### Scoped law / quotient revision

The V45–V68 quotient/refinement line established that equivalence is indexed by verifier and scope. Real external separator events split coarse equivalence classes. V68 implemented incremental reversible Lawbook refinement: local splits preserved unrelated classes/provenance, reversal restored the prior partition, and refinement could expose capability hidden by a coarser quotient.

### IKKF V1 — reproducible fresh capability compilation — ATTESTED WITH CORRECTION

Primary harness/protocol/result were checked directly. B0, C1, C2, J, U and R are separately executed. C1 and C2 are separate fresh compilation calls and each reaches 100% on 32 held-out source-distinct cases; J and U remain 0%; reload R remains 100%; held-out programs/suffixes are not gradient inputs.

## Evidence / attestation discipline

A CI `success` is not automatically a scientific pass, and a CI `failure` is not automatically a scientific negative. A prose summary is not primary evidence. A gate name must not claim more than its predicate checks.

Classify headline claims as **ATTESTED**, **BOUNDED PASS**, **NEGATIVE**, **INCOMPLETE/INFRASTRUCTURE**, or **REPORTED/NEEDS ATTESTATION**.

The IKKF V1 correction is the precedent: a separate second execution is attested; stochastic independence is not.

## Remaining capstone questions

### 1. Natural development

Reproduce V54-shaped developmental compounding on naturally occurring, pre-existing heterogeneous worlds with human/fixed solutions sealed until termination. V55A says the current natural adapter/constructor still exposes too few usable worlds.

### 2. Constructor development

Establish `Constructible(K0) ⊊ Constructible(K1)` and ideally a two-generation `K1 -> K2` lineage. V55B is a real negative for one meta-substrate; V56B did not reach a verdict because of a harness crash.

### 3. Scale / economic value

Move V56C's verifier-controlled model-layer result beyond the 12-case smoke benchmark to meaningful coding-agent workloads under matched sequential budgets. Compare base, raw memory, ordinary adaptation and LOGOS; measure held-out solves, tool calls/tokens, verifier interactions, latency/cost, regressions, uninstallability and performance as verified experience accumulates.

### Attestation is a precondition, not a fourth equal claim

Every Discover -> Verify -> Install -> Invoke -> Compile -> Revise transition used in a headline must be reproducible from primary evidence: verifier output, hashes, scope, provenance, controls/counterexamples and causal ablations where applicable.
